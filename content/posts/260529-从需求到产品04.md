直接我们说了需求侧主要是了解清楚“大致需求”和“具体需求”。
接下来的案例顾客需求和开发（甲乙方）都是我自己，因为我想做一款产品。


## 1.1 大致需求
做一款亲密关系记录、学习、分享、成长的APP。
非交友APP，也不是主要用来社交的平台（但支持社交功能），主要是帮助年轻人学会恋爱、经营关系、实现共同成长的个人成长型产品

## 1.2 明确需求
- 方向：恋爱、亲密关系记录、学习、分享、成长的APP。
- 出发点：自己处于恋爱关系当中，觉得很有必要，主要是对这类想要对恋爱有良性发展、成长的年轻人群体。
- 受众、对象：18-32岁、对恋爱关系想良性健康发展、想学习和成长的偏高质量三观的年轻人。
- 目的：让年轻人慢慢会经营好一段亲密关系，学会处理和良好对待日常的琐事，学会应对各类矛盾，主要还是整体上让用户自己能够慢慢成长、变化。
- 具体业务需求和业务流程会放在后文的1.4部分，这块内容比较多，这块是甲乙方都互相沟通确认的一个点，很多时候甲方都不明确，我们自己设计沟通的。
- 内部数据资料：目前是打算直接对这种恋爱亲密关系的经验分享帖、一些恋爱日常记录帖、恋爱相关书籍知识的内容进行整理，提前设计一些真实的数据，这些数据从小红书、公众号、相关书籍等上面找，后面会专门整理这块数据，因为还有用户信息、图片、对话、评论、点赞、等等数据。
- 边界：产品业务的大边界就是不是用来找搭子找对象的，而是记录恋爱、学习恋爱、学习成长型的产品，但是也有社交功能，但主要还是记录、学习、分享的。各环节的边界点得撰写1.4的时候来分析明确。开发的边界点暂时没有，感觉都可实施。

## 1.3 MVP、Demo
这块同AI沟通交流出一版PRD，然后让与AI沟通开发一个基础版本（或者Demo），然后自己分析+与顾客沟通确认，然后再明确，最终有一个大致明确的内容，接着就可以进入到1.4的具体需求与功能的内容板块了。

## 1.4 具体需求与功能
这块是很重要的，明确的输入往往能够得到不错的输出！
这时候必须要有笔和纸，一个一个写、画、记录下来，然后整理编写。与AI沟通、与AI一起设计（可以多个AI一起来），1+1>3。

## 一、产品概述

### 1.1 产品定位

《同舟》是一款面向大致18-32岁年轻人的**亲密关系陪伴与成长空间**（并非一定是该年龄段的人）。这里没有课程和作业，只有同龄人之间真诚的分享、记录和陪伴。

**核心差异点：**
- ❌ 不是交友软件，目的不是找对象
- ❌ 具有社交能力但主要方向不是社交媒体
- ✅ 是成长工具（帮助用户建立正确的恋爱观、提升经营关系的能力）
- ✅ 是记录工具（帮助用户记录恋爱过程中的学习、甜蜜与冲突）
- ✅ 是经验社区（同龄人之间真诚分享经验，互相学习）
- ✅ 帮助用户建立正确的恋爱观、提升经营关系能力、提问和回答一些相关经验等

### 1.2 产品目标

1. 让用户在轻松的浏览和分享中，自然而然地获得恋爱经营的启发
2. 让用户愿意随手记录恋爱中的点滴，形成"记录即成长"的松弛感
3. 陪伴一代年轻人成为更好的恋爱伴侣，在相处中彼此成就

### 1.3 核心设计理念

| 理念 | 说明 |
|-----|------|
| **节制设计** | 产品不追求用户时长，主动提醒用户"去实践"、"去休息" |
| **真诚导向** | 社区氛围以真实分享为主，反对套路、反对炫耀、反对性别对立 |
| **成长自然发生** | 不刻意追踪进度，让成长在分享和记录中自然沉淀 |
| **同频学习** | 相似背景的用户看到适合自己的内容 |

## 二、目标用户

### 2.1 用户画像

**基础属性：**
- 年龄：大部分是18-32岁（并非用户必须是该年龄段的用户）
- 性别：男性和女性均适用（可保密）
- 状态：单身但有喜欢的人、暧昧中、恋爱中、刚分手想复盘、想好好学习恋爱经营的想成长的人。

**心理特征：**
- 对亲密关系有向往，但缺乏系统化的学习和指导
- 愿意自我反思和成长，不认为"恋爱就是凭感觉"
- 希望在恋爱中成为更好的自己，也希望成就对方
- 对现有的"恋爱话术App"或"情感导师"有抵触或不信任

**使用场景：**
- 和对象吵架了，不知道该怎么沟通，来查一下相关内容和经验
- 想给对象准备惊喜，来看看同年龄段人的创意
- 记录今天和对象的甜蜜时刻或矛盾，做成长记录
- 花5-10分钟学习一个恋爱知识点（比如从别人的分享帖子当中学习）
- 记录日常生活和想法感悟等

### 2.2 用户分层（非段位，是需求分层）

| 分层 | 特征 | 核心需求 |
|-----|------|---------|
| **探索期** | 真正恋爱次数0-1次或者重新开始恋爱 | 根据用户个人特征，探索恋爱的一些方式方法 |
| **建立期** | 真正恋爱次数2-3次或者以及恋爱相处了1-2年 | 学习深度沟通、冲突处理、长期关系维护 |
| **深耕期** | 真正恋爱次数3次以上或长期关系 | 学习共同成长、未来规划、亲密关系升级 |

## 三、核心功能模块

### 3.1 段位测评系统

#### 3.1.1 测评入口
- 新用户注册后完成测评（作为个性化基础）
- 个人页面可随时重新测评
- 每次重新测评会记录历史，生成成长曲线（个人页重新测评里有历史线）

#### 3.1.2 测评维度

| 维度 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| 恋爱次数 | 单选 | 是 | 0次 / 1次 / 2-3次 / 4次以上 |
| 恋爱体验 | 单选 | 是 | 差 / 中规中矩 / 不错 |
| 年龄 | 数字输入 | 是 | 备注：（提醒建议是17-33岁的人使用，当然超出也可以）|
| 自我形象满意度 | 单选 | 是 | 1星-5星（很不满意→很满意） |
| 自我感觉恋爱观评分 | 单选 | 是 | 1星-5星（恋爱观的良性状况） |


#### 3.1.3 段位等级

共四级，由系统根据测评结果自动计算：

| 段位 | 分值区间 | 典型特征 |
|-----|---------|---------|
| **小白舟** | 0-25分 | 恋爱经验极少或体验较差，需要基础认知建设 |
| **铂金舟** | 26-50分 | 有一定经验但尚不稳定，需要系统学习方法 |
| **钻石舟** | 51-75分 | 经验较丰富且体验良好，可以输出经验帮助他人 |
| **荣耀舟** | 76-100分 | 经验丰富、自我认知清晰，可作为社区优质内容贡献者 |

段位名称可以不采用这些，换个表达，契合产品主题的。

#### 3.1.4 段位展示规则
- 个人主页醒目位置展示当前段位（带图标）
- 社区发帖/评论时，头像旁显示当前段位
- 段位提升时，系统推送祝贺通知，并生成"成长报告"卡片（可查看）
- 段位历史在个人页以时间轴形式展示（历史段位点击后展示）

#### 3.1.5 段位计算权重（V1.0版本）

待设计。

**注**：V1.0可以考虑采用固定权重，后续根据用户数据和行为反馈迭代调整，考虑这块会采用后台AI某些接口简单分析得到。

### 3.2 感情状态系统

#### 3.2.1 可选状态
- 🌱 **自我成长中**（暂时不想/没有恋爱，专注提升自己）
- 🔍 **追寻中**（有喜欢的人，正在追求/被追求）
- 💕 **暧昧中**（关系未确定，正在互相了解）
- ❤️ **恋爱中**（已确定恋爱关系）
- 💔 **冷静期**（刚分手，需要复盘和成长）

### 3.3 内容系统

#### 3.3.1 内容类型

**A. 精选内容（官方内容或者用户分享发布的内容审核到这里头）**
- 由运营团队整理的真实故事、经验总结、相关书籍理论等，风格像朋友聊天而非教学
- 用户分享的帖子（申请了精选），我们审核通过了的优质帖子
- 按主题分类（如：1. 多方面的；2. 礼物、浪漫、分享；3. 约会、去一起住酒店等的；4. 沟通、陪伴；5. 矛盾、争吵；6. 其他）。不按段位强制分级
- 内容方向：真实经历、过来人的经验、温暖的提醒、有趣的观察等等

**B. 社区帖子（UGC内容）**
- 图文形式，类似小红书但更简单克制
- 用户可发文字+图片（最多5张）
- 必须选择内容倾向标签（见3.3.2）

**C. 随手记（个人私密内容）**
- 用户随手写下当下的想法、感受、想记住的事
- 可选择公开（作为社区帖子发布）或仅自己可见
- **无积分、无打卡、无连续天数统计，纯粹是个人空间**

#### 3.3.2 内容倾向标签体系（发帖必填）

每篇帖子/文章必须选择一个倾向标签：

| 标签 | 图标 | 说明 |
|-----|------|------|
| **男生成长向** | 👦 | 帮助男生理解女生心理、提升表达力、学习经营关系等 |
| **女生成长向** | 👧 | 帮助女生建立沟通自信、设立健康边界、学习经营关系等 |
| **共同成长向** | 💑 | 双方都需要知道的：冲突处理、长期规划、亲密维护等 |
| **通用认知向** | 📖 | 底层知识：心理学原理、依恋理论、沟通模型等 |
| **其他** | 🌟 | 不属于以上分类的分享 |


**用户偏好设置：**
- 用户可在个人设置中选择"优先看哪些倾向的内容"（多选，默认全选）
- 首页推荐会参考偏好，但不会完全屏蔽未选中的内容（保留异性视角的学习机会）
- 社区页面顶部有倾向标签筛选栏，用户可手动切换查看

#### 3.3.3 内容推荐逻辑（V1.0）

推荐不追求算法精准，追求"合适即可"：
- 推荐内容会有随机的策略，推荐和排序都具有较大的随机。
- 随机的同时会考虑一下用户的偏好，但不是完全精准推荐偏好。

**内容浏览是完全自由的**，想看就看，不想看就划走，不追求"完成感"。

### 3.4 情侣记录系统

#### 3.4.1 记录类型

| 类型 | 说明 | 可选字段 |
|-----|------|---------|
| **甜蜜时刻** | 记录开心、感动、浪漫的时刻 | 心情评分、地点、配图 |
| **矛盾/吵架** | 记录冲突事件，用于后续复盘 | 起因、双方反应、解决方式、是否已和解 |
| **过节/纪念日** | 记录重要日期和庆祝方式 | 日期、礼物、花费、对方反应 |
| **里程碑** | 关系中的重要节点 | 日期、意义说明 |
| **日常记录** | 平凡的但想记住的小事 | 文字+图，无固定字段 |

#### 3.4.2 记录功能设计
- 每条记录可选择、"公开"、"仅自己可见"或"伴侣可见"（未来可扩展伴侣绑定功能）
- 支持按时间轴查看所有记录
- 支持按类型筛选
- 支持生成"月度感情报告"（自动统计：本月甜蜜时刻占比xxx、矛盾占比xxx）
- 顶部再放一个吊坠样式的卡片，里面随机切换一些记录内容（切换轮播？或者考虑比较不错的方案，有不同的样式风格和主题）

### 3.5 社区互动系统

#### 3.5.1 帖子浏览
- 列表展示：封面图+标题+摘要+作者头像/段位/倾向标签
- 点击进入详情页：图片轮播+完整内容+评论区
- 支持按倾向标签筛选、按时间/热度排序
- 发布用户点击名称或者头像会进入到对应的相关资料（不公开/公开），基本资料和分享内容。
- 帖子可以评论、回复、点赞喜欢

#### 3.5.2 帖子可见范围（发帖时选择）

| 可见范围 | 说明 |
|---------|------|
| **公开** | 所有用户可见 |
| **匿名** | 内容公开，但隐藏作者信息（头像、昵称、段位仍显示为匿名） |
| **隐藏** | 仅自己可见 |
| **同段位可见** | 仅与自己当前段位相同的用户可见 |

**同段位可见的设计意图**：保护新手用户的表达欲，避免高段位用户的"降维打击"，让相似经验的人能更真诚地交流。

#### 3.5.3 互动功能
- **点赞**：点击爱心，作者收到通知
- **收藏**：收藏到个人"收藏夹"，可分类管理
- **评论**：文字评论，评论者段位显示在评论旁
- **关注与聊天**：点头像或者昵称可以关注或者聊天
- **分享**：生成图片卡片，可以保存，可以分享到微信/QQ（外部）

#### 3.5.4 评论区设计
- 评论按时间倒序排列
- 每条评论显示：评论者头像、昵称、当前段位、评论内容、时间、ip定位
- 评论者段位快照：评论时记录评论者当时的段位，即使后续段位提升，该评论仍显示原段位（保留历史真实性）
- 作者可置顶一条评论
- 支持回复评论（二级评论，最多一层嵌套）
- 风格：与小红书很类似

### 3.6 通知系统

#### 3.6.1 通知类型

| 类型 | 触发条件 | 通知内容 |
|-----|---------|---------|
| 评论通知 | 有人评论你的帖子 | "xxx评论了你的帖子《标题》" |
| 点赞通知 | 有人点赞你的帖子 | "xxx赞了你的帖子" |
| 收藏通知 | 有人收藏你的帖子 | "xxx收藏了你的帖子" |
| 系统通知-段位提升 | 段位提升时 | "恭喜你晋升为黄金段位！查看成长报告" |
| 系统通知-状态指南 | 感情状态变更时 | "你设置了'恋爱中'，为你准备了一份过渡指南" |
| 系统通知-使用提醒 | 使用时长/频率触发 | "看你今天看了好一会儿了呢，要自己去干点别的嘛～" |

#### 3.6.2 通知展示
- 顶部导航栏有铃铛图标，红点提示未读数量（首页和看看页）
- 通知列表页按时间倒序排列
- 支持标记全部已读
- 支持删除单条通知

### 3.7 节制使用提醒系统

产品主动限制用户使用时长，体现"为你好"的设计理念：

| 触发条件 | 提醒方式 | 大致文案（不是非要使用该文案，可设计一些不错的） |
|---------|---------|------|
| 单次使用超过45分钟 | 弹窗拦截 | "今天已经看很久了，最好的成长是去实践。放下手机，去和TA聊聊天吧～" |
| 连续刷社区超过25分钟 | 底部提示条 | "与其看别人，不如记录你们的故事？" |
| 深夜23:00-06:00使用 | 弹窗提示 | "深夜容易情绪化，建议早点休息。好的恋爱也需要好的睡眠呢💤" |
| 单日打开超过8次 | 系统通知 | "你今天很积极！记得来这里是为了更好地相处，不是代替相处哦" |
| 每周打开5-7天 | 系统通知 | "这周经常来呀，有什么想记录的吗？" |

**用户可关闭提醒**：在设置中可选择关闭部分提醒，但默认开启。

## 四、用户流程

### 4.1 新用户注册流程

```
打开App → 欢迎页（产品理念介绍，轮播或者滑动切换，带有古文和现代文的Slogan）→ 手机号注册/登录 → 
填写基础资料（昵称、头像、性别、年龄）→ 
完成段位测评→ 查看段位结果和成长建议 → 
设置感情状态 → 进入首页（看到首批推荐内容）
每操作一个板块，后台入库并同步!
```
